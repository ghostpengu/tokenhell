# TokenHell research findings

Research date: 2026-11-06. This is a source survey and a read-only, schema-only inspection of this Mac, not a live test of authenticated endpoints. Formats and undocumented endpoints can change; verify against pinned client versions before shipping.

## 1. Data sources per tool

### Interpretation and common pitfalls

Local history is a **partial, device-local record**; provider quota is usually **account-wide and server-calculated**, potentially including other devices and products. A locally reconstructed token count cannot reliably predict a 5-hour or weekly percentage. API organization reports can overlap the same requests in local transcripts: show scope and provenance and do not sum across sources without a proven request-level join. Subscription users' list-price equivalent is an **estimate, not a charge**. Null, absent, stale, unauthorized, and zero must remain distinct. For counts, preserve raw provider semantics: cached input and reasoning output can be subsets, while some clients record input and caches as disjoint categories.

Machine inspection found Claude and Codex session files. No matching Gemini, OpenCode, Pi, or legacy Amp files were found in the specific default globs inspected; this is not proof those tools are absent elsewhere. Only allowlisted structure was emitted; no content, identifiers, credential values or original token counts were copied. The following are synthetic redactions of observed keys, not literal transcript lines:

```json
{"type":"assistant","timestamp":"<redacted>","requestId":"<redacted>","message":{"id":"<redacted>","model":"<redacted>","usage":{"input_tokens":"<number>","output_tokens":"<number>","cache_read_input_tokens":"<number>","cache_creation_input_tokens":"<number>","cache_creation":"<object>","output_tokens_details":"<object>"}}}
{"timestamp":"<redacted>","type":"event_msg","payload":{"type":"token_count","info":{"total_token_usage":{"input_tokens":"<number>","cached_input_tokens":"<number>","cache_write_input_tokens":"<number>","output_tokens":"<number>","reasoning_output_tokens":"<number>","total_tokens":"<number>"},"last_token_usage":"<object>","last_usage_includes_reasoning":"<value>","model_context_window":"<value>"},"rate_limits":{"limit_id":"<value>","limit_name":"<value>","primary":{"used_percent":"<value>","window_minutes":"<value>","resets_at":"<value>"},"secondary":"<object>","credits":"<object>","plan_type":"<value>"}}}
```

### Claude Code

- **History:** `~/.claude/projects/**/*.jsonl`, including subagent directories; honor `CLAUDE_CONFIG_DIR` and alternate configured roots. Each assistant record has `timestamp`, `requestId`, `message.id`, `message.model`, and `message.usage` containing `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, and sometimes `cache_creation` TTL splits and `output_tokens_details`. Ordinary Claude input and cache read/write are separate buckets. Reasoning may not be separately reported; do not infer it from message content. Older or partial records may omit fields. Source: [ccusage](https://ccusage.ryoppippi.com/) and [ClaudeCodeUsage](https://github.com/ClaudeCodeUsage/ClaudeCodeUsage).
- **Dedup:** multiple streamed transcript records can represent one response. Merge the latest complete usage for `(requestId, message.id)`, not every line; handle missing IDs conservatively and don't collapse unrelated records. Include subagent transcripts, but avoid copies and imported duplicates. [A working implementation](https://github.com/ZhuoQiuMcgill/cc-usage) describes this composite key.
- **Limits:** yes, for eligible Claude.ai OAuth accounts: undocumented `GET https://api.anthropic.com/api/oauth/usage` with Bearer access token and `anthropic-beta: oauth-2025-04-20`. Typical JSON includes `five_hour`, `seven_day`, optional `seven_day_sonnet` / `seven_day_opus`, each with utilization and reset; optional extra usage may exist. `user:profile` scope is needed; missing/null windows are unavailable, not zero. macOS CLI credential item is commonly `Claude Code-credentials`, or `~/.claude/.credentials.json` on file-backed installs. Account scope can exceed CLI history. [CodexBar implementation notes](https://github.com/steipete/CodexBar/blob/main/docs/claude.md). **Reliability:** local format observed but undocumented; OAuth endpoint undocumented, contingent on scope, account and policy. Avoid refreshing or rewriting another app's credential store; let the owner refresh.

### OpenAI Codex CLI

- **History:** `$CODEX_HOME/sessions/YYYY/MM/DD/*.jsonl` and `archived_sessions/**/*.jsonl`, default `~/.codex/`. `event_msg` / `payload.type=token_count` contains `info.total_token_usage` (cumulative), `info.last_token_usage`, `model_context_window`, and sometimes `rate_limits`. Fields in each usage object observed locally: `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`, `total_tokens`; event `timestamp`. Model comes from preceding `turn_context.payload.model`, not reliably the token event. Cached input is included in input; reasoning generally is included in output, subject to version-specific flags. Cache-write semantics and pricing vary by model. [ccusage Codex guide](https://github.com/ccusage/ccusage/blob/main/docs/guide/codex/index.md).
- **Dedup:** do not sum cumulative totals or blindly sum every repeated `last_token_usage`: take per-session cumulative deltas, detect repeated snapshots and counter resets, attribute deltas to the contemporaneous model; handle separate `token_usage_record` and compaction carefully so already-accounted usage is not counted twice. Cross-file imported/copied sessions require stable session/event identity. ccusage documents its matched compaction handling and historical model fallback; show unknown model when unsupported rather than inventing it.
- **Limits:** local `rate_limits.primary` and `secondary` expose `used_percent`, `window_minutes`, `resets_at`, plus `credits`, `plan_type` and limit IDs; these are snapshots, not guaranteed current and can be absent. For live data use installed `codex app-server` JSON-RPC `account/rateLimits/read` after `initialize`; it returns primary/secondary windows and credits. Alternatively CodexBar uses undocumented `GET https://chatgpt.com/backend-api/wham/usage`, account-scoped OAuth credentials from `$CODEX_HOME/auth.json` or supported credential storage; let Codex own refresh. API-key usage and ChatGPT subscription quota are distinct. [CodexBar sources](https://github.com/steipete/CodexBar/blob/main/docs/codex.md); [OpenAI app-server protocol](https://developers.openai.com/codex/app-server/). **Reliability:** observed local schema, official app-server integration subject to version, undocumented web endpoint.

### Gemini CLI

- **History:** `$GEMINI_CLI_HOME/tmp/<project_hash>/chats/*.json`, default `~/.gemini/tmp/`; session JSON has `sessionId` and `messages[]`. Gemini messages carry `id`, `timestamp`, `model`, and `tokens.input`, `output`, `cached`, `thoughts`, `tool`, `total` when available. `cached` is cached content within prompt tokens; thoughts/tool counts have distinct semantics, so preserve them rather than assume disjointness. Cache write is not separately established by this schema. Dedup by session ID plus message ID, treating files as mutable snapshots, not additive files; account for copies. [Official session docs](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/session-management.md), [schema](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/chatRecordingTypes.ts).
- **Limits:** yes for eligible CLI OAuth accounts through undocumented `POST https://cloudcode-pa.googleapis.com/v1internal:retrieveUserQuota`, project ID from `loadCodeAssist`; buckets report `modelId`, `remainingFraction`, `resetTime`. Gemini CLI OAuth credentials are file-backed, commonly `~/.gemini/oauth_creds.json`; do not copy contents. The Gemini app's web quota is a different source. CodexBar reports a consumer-tier migration in June 2026; check account eligibility and current Google policy rather than promising universal availability. [CodexBar Gemini](https://github.com/steipete/CodexBar/blob/main/docs/gemini.md). **Reliability:** official persisted sessions, internal quota endpoint.

### Cursor

- **History:** desktop `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` is SQLite and may contain auth and application state. It is **not a verified complete token ledger**; tokscale specifically reads the app token from it and uses Cursor's usage-events API, rather than treating local SQLite as the source of truth. Cursor API data is account-wide; tokscale writes its own cache under `~/.config/tokscale/cursor-cache/usage*.json`. Tokens/model/timestamp and dedup key depend on the events response and version; confirm the live schema and stable event IDs before implementing. Do not scrape arbitrary `ItemTable` contents. [Tokscale source notes](https://github.com/junhoyeo/tokscale#cursor-ide).
- **Limits:** undocumented `GET https://cursor.com/api/usage-summary` reports included/on-demand usage and billing cycle; `GET /api/usage?user=ID` is a legacy request-based source. Some accounts expose weekly Grok Bot `usagePercent` and `nextResetTimestampUtc` via `POST /api/dashboard/get-sand-usage-status`. An authenticated Cursor app token or browser session may be used; browser-cookie decryption can prompt Keychain and carries extra privacy/maintenance cost. [CodexBar Cursor](https://github.com/steipete/CodexBar/blob/main/docs/cursor.md). **Reliability:** reverse-engineered, account and version dependent; do not claim universal local per-token coverage.

### GitHub Copilot

- **History:** CLI `~/.copilot/session-store.db`, desktop `~/.copilot/data.db`, or opt-in OTEL JSONL `~/.copilot/otel/*.jsonl` / `COPILOT_OTEL_FILE_EXPORTER_PATH`. Tokscale prefers exported OTEL for sessions that also have SQLite events. Chat spans can have `gen_ai.response.model`, `gen_ai.conversation.id`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.reasoning.output_tokens`, timestamps and trace/span IDs; cache-write not established. Dedup snapshots by compatible trace+span identity and choose one source per session; do not add cumulative metrics or tool spans to chat spans. The local SQLite schema is version dependent; inspect its adapter before claiming exact columns. [Tokscale Copilot](https://github.com/junhoyeo/tokscale#copilot-cli).
- **Limits:** undocumented `GET https://api.github.com/copilot_internal/user` using an authorized GitHub OAuth token returns quota snapshots, including premium interactions and reset information where exposed; snapshots may represent the same pool, so do not add them. Official [GitHub billing usage REST API](https://docs.github.com/en/rest/billing/usage) can report billed Copilot units and model for eligible account/admin scopes, but is not a per-token ledger. [CodexBar Copilot](https://github.com/steipete/CodexBar/blob/main/docs/copilot.md). **Reliability:** observed third-party local parsers, internal quota endpoint; official billing API scope varies.

### OpenCode

- **History:** `$XDG_DATA_HOME/opencode/opencode.db` and channel databases `opencode-<channel>.db` (usually `~/.local/share/opencode/`); pre-migration `storage/message/<sessionId>/*.json`. Assistant message data contains `id`, `modelID`, `providerID`, `tokens.input`, `output`, `reasoning`, `cache.read`, `cache.write`, `cost`, and time metadata. Read SQLite read-only including WAL; dedup by message ID across databases and migrated legacy data, not by timestamp. [Tokscale OpenCode format](https://github.com/junhoyeo/tokscale#opencode).
- **Limits:** no universal local limit across arbitrary provider connections. OpenCode Go/ZEN account quota can be obtained via provider-specific account API or authenticated dashboard, with rolling/weekly/monthly windows when provided; BYO provider limits belong to that provider. [CodexBar providers](https://github.com/steipete/CodexBar/blob/main/docs/providers.md). **Reliability:** open-source local schema, provider-specific undocumented remote integration.

### Amp

- **History:** legacy local `~/.local/share/amp/` thread data may exist; current tokscale uses an explicit server sync into its own `~/.config/tokscale/amp-cache/threads/`, not a guaranteed native local ledger. Schema and per-message token field availability vary; no verified complete native field map or dedup rule beyond stable thread/message identities was established. Avoid promising cache or reasoning fields. [Tokscale](https://github.com/junhoyeo/tokscale).
- **Limits:** `amp usage` is a practical authenticated CLI source for balances and allowances. CodexBar also uses undocumented `POST https://ampcode.com/api/internal?userDisplayBalanceInfo`, or browser settings as fallback. Allowance, credit balance and reset depend on plan; not necessarily a token quota. [CodexBar Amp](https://github.com/steipete/CodexBar/blob/main/docs/amp.md). **Reliability:** CLI supported behavior; internal endpoint and legacy web format undocumented.

### Factory Droid

- **History:** `~/.factory/sessions/` contains session JSONL; tokscale supports local usage parsing. Exact token field names, stable identifiers and handling of cumulative versus per-request updates were not independently verified here; validate against the installed version and fixtures before supporting input/output/cache/reasoning totals. Do not equate status snapshots with individual requests. [Tokscale supported sources](https://github.com/junhoyeo/tokscale).
- **Limits:** undocumented `GET https://api.factory.ai/api/billing/limits` can return 5-hour, weekly and monthly windows; `GET https://app.factory.ai/api/organization/subscription/usage` reports subscription usage and billing window. Factory API key or account session may be needed. [CodexBar Factory](https://github.com/steipete/CodexBar/blob/main/docs/factory.md). **Reliability:** community-observed local format and private APIs; plan dependent.

### Kimi CLI and Kimi Code

- **History:** `~/.kimi/sessions/<group>/<session>/wire.jsonl` has `timestamp`, `message.type=StatusUpdate`, `message.payload.token_usage.input_other`, `output`, `input_cache_read`, `input_cache_creation`, and `message_id`. Model is not guaranteed in that update; resolve from session metadata only when authoritative, otherwise unknown. Dedup repeated status updates by session plus message ID and understand whether a revision replaces prior usage. Kimi Code uses `~/.kimi-code/sessions/<workdir>/<session>/agents/<agent>/wire.jsonl`: `type=usage.record`, `model`, `usage.inputOther`, `output`, `inputCacheRead`, `inputCacheCreation`, `usageScope`, `time`; distinguish turn/session scope and copies. Reasoning breakdown not established. [Tokscale Kimi formats](https://github.com/junhoyeo/tokscale#kimi-cli).
- **Limits:** Kimi Code account API/auth can expose session and weekly quotas; credentials and scope vary. See [CodexBar provider strategies](https://github.com/steipete/CodexBar/blob/main/docs/providers.md). **Reliability:** local and quota formats community-observed, not a stable public integration contract.

### Qwen CLI

- **History:** `~/.qwen/projects/<project>/chats/<chat_id>.jsonl`, records `type`, `model`, `timestamp`, `sessionId`, `usageMetadata.promptTokenCount`, `candidatesTokenCount`, `thoughtsTokenCount`, `cachedContentTokenCount`. Cache-write is not established. Use stable message ID if present, otherwise file/session plus record offset; verify retries or copied files before deduping across files. [Tokscale Qwen](https://github.com/junhoyeo/tokscale#qwen-cli).
- **Limits:** Qwen Cloud / Alibaba subscription limits depend on the specific product and account; CodexBar documents browser-session 5-hour/weekly Token Plan APIs. No universal local quota for all Qwen CLI backends. **Reliability:** community-observed files and undocumented provider APIs. [Provider matrix](https://github.com/steipete/CodexBar/blob/main/docs/providers.md).

### Pi

- **History:** `~/.pi/agent/sessions/<encoded-cwd>/*.jsonl`; `type=message` assistant records contain `id`, `timestamp`, `message.provider`, `message.model`, `message.usage.input`, `output`, `cacheRead`, `cacheWrite`, `totalTokens`, sometimes cost. Separate `usage`, `compaction`, `branch_summary` and tool-result records can also carry billable usage; standalone records have their own IDs and may have model/provider. Reasoning is not reliably separate. Dedup by session/record identity, accounting for copied entries, not just parent message. Do not charge model-less tool/summary usage to a guessed preceding model. [Tokscale Pi](https://github.com/junhoyeo/tokscale#pi).
- **Limits:** none universal: Pi is a client for multiple provider credentials, so query the actual provider if an eligible endpoint exists. **Reliability:** open session format, no shared quota service.

### Anthropic raw API / Admin

- **History/cost:** official legacy `GET https://api.anthropic.com/v1/organizations/usage_report/messages` and `/v1/organizations/cost_report` require an Admin credential, not an ordinary inference key. Time buckets use `starting_at`/`ending_at`, `bucket_width`, `results`, pagination; group by model/workspace and other supported dimensions. Usage includes `uncached_input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation.ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens`. Reasoning is not separately guaranteed. Cost API is billing data rather than local list-price estimation. Upsert by organization, bucket boundaries and all group dimensions, and replace revised buckets rather than adding repeated pages. [Official legacy docs](https://platform.claude.com/docs/en/manage-claude/usage-cost-api).
- **Current status/limits:** Anthropic now recommends its [Usage and Cost Analytics API](https://platform.claude.com/docs/en/manage-claude/usage-cost-analytics-api) for new integrations; it documents freshness and revisions. Organization reports do not give live Claude subscription 5-hour/weekly windows. API response rate-limit headers are request-time snapshots; see [Anthropic rate limits](https://platform.claude.com/docs/en/api/rate-limits). **Reliability:** official; aggregate data can be delayed or revised and covers API organization only.

### OpenAI raw API / Admin

- **History/cost:** official `GET https://api.openai.com/v1/organization/usage/completions` and `/v1/organization/costs` need an organization Admin key; ordinary inference API keys are insufficient. Completions buckets have `start_time`, `end_time`, `input_tokens`, `output_tokens`, `input_cached_tokens`, `input_cache_write_tokens` and optional TTL-specific writes; `model` is populated when grouped. Input includes cache reads/writes. Reasoning is not a separately documented field in this aggregate response. Group by model/project/key as needed, follow `next_page`, upsert complete bucket + dimensions and allow revisions. Other endpoints cover embeddings/audio etc. [Official completions schema](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/completions), [cost/usage endpoints](https://developers.openai.com/api/reference/go/resources/admin/subresources/organization/subresources/usage).
- **Limits:** not ChatGPT/Codex subscription windows. API request rate-limit headers and project configuration are different, model/organization-scoped controls; an aggregate history report is not a live remaining-limit feed. [OpenAI rate limits](https://developers.openai.com/api/docs/guides/rate-limits). **Reliability:** official, aggregated and account-scoped.

### OpenRouter raw API

- **Credits:** official `GET https://openrouter.ai/api/v1/credits` returns `data.total_credits` and `data.total_usage`; difference is remaining credit, not a per-model token ledger or a reset window. Requires a suitable provisioning key. [Credits documentation](https://openrouter.ai/docs/api/api-reference/credits/get-credits). For the current key, [GET /api/v1/key](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-key) provides key limit/usage/reset information where configured; key and account totals are different scopes. Dedup snapshots by key/account and observation time; replace, do not sum them. **Reliability:** official, subject to key permissions; no 5-hour/weekly inference quota should be fabricated.

## 2. Prior art and pricing

### ccusage

[ccusage](https://github.com/ccusage/ccusage) is MIT licensed and provides local session/day/month token and price reports for multiple agents. Its Codex guide documents cumulative-counter deltas, compaction and model/tier pricing edge cases. It is a history/cost reporter; do not mistake rolling local blocks for provider-enforced quota. Reuse ideas and fixtures under license, especially dedup and model fallback handling.

### CodexBar

[CodexBar](https://github.com/steipete/CodexBar) is an MIT-licensed macOS menu-bar app with many providers. Its [provider matrix](https://github.com/steipete/CodexBar/blob/main/docs/providers.md) describes OAuth, app-server/CLI, browser-cookie, internal API and local fallbacks, plus local Claude/Codex cost scans. Learn from source labels, account selection, noninteractive Keychain policy, stale-state handling and reset display; provider connectors need maintenance. Reuse code only with the MIT notice and after checking any bundled component's own license.

### Tokscale

[Tokscale](https://github.com/junhoyeo/tokscale) is MIT licensed, Rust-based, scans numerous agent formats, supports quota integrations and optional hosted/leaderboard features. It is particularly useful for discovery, examples, parser boundaries and cross-source dedup. Its provider coverage is much broader than can be validated on this Mac; validate schemas against actual client versions. Do not enable uploads by default merely because prior art supports them.

### AI Usage Monitor

[AI Usage Monitor](https://github.com/stavrop/ai-usage-monitor) is an Apache-2.0 macOS menu-bar app for Claude and ChatGPT usage windows. Its provider-specific account polling and visual alert patterns are useful examples for a compact quota-first interface; it is not evidence of comprehensive local token accounting. Follow Apache notice and attribution requirements if copying.

### Pricing data

[LiteLLM's model cost map](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json) provides machine-readable model pricing, token categories and context metadata; [OpenRouter models API](https://openrouter.ai/docs/api/api-reference/models/get-models) supplies provider-facing pricing. Vendor pricing pages and billed cost APIs remain authoritative for actual charges. Version and date the price table, keep aliases/provider and service tier explicit, preserve unknown price as unknown, and handle cache-write TTL, batch/priority, long-context thresholds, tools and currency. Local logs often lack enough information for exact invoices; label results API-equivalent estimates. Avoid adding reasoning to output twice. Provider routing and subscription pricing may differ.

## 3. Tauri v2 menu bar, glass and storage

### Tray-only shell and positioning

Use Tauri v2's `tray-icon` feature and `TrayIconBuilder`, retain the tray object, and create a hidden, undecorated small window. Set `ActivationPolicy::Accessory` on macOS at startup so the app has no Dock icon while retaining window interaction; consider `LSUIElement` packaging behavior and test activation/focus and quit behavior in a bundled app. Toggle the panel on tray click, place it from the tray icon rectangle with monitor bounds and scale-factor awareness, and hide on `WindowEvent::Focused(false)` while handling transient native dialogs. Tauri's [tray docs](https://v2.tauri.app/learn/system-tray/) and [activation policy API](https://docs.rs/tauri/latest/tauri/enum.ActivationPolicy.html) cover the primitives. [tauri-plugin-positioner](https://v2.tauri.app/plugin/positioner/) offers `TrayCenter` and constrained positioning; forward tray events to it. This is a positioned window, not automatically an AppKit `NSPopover`; use an AppKit panel bridge if true native popover semantics are essential.

`TrayIcon::set_title` / JS `setTitle` can update text on macOS; `set_icon_as_template` / `setIconAsTemplate` marks monochrome icons for system recoloring. Keep title updates bounded to avoid layout churn and allow an icon-only mode. [Tauri tray API](https://v2.tauri.app/reference/javascript/api/namespacetray/). Test multiple monitors, menu-bar overflow, light/dark appearance, fast clicks and focus changes.

### Liquid Glass and fallback

[window-vibrancy](https://github.com/tauri-apps/window-vibrancy) is MIT/Apache-2.0, supports `apply_liquid_glass` on macOS 26+ since 0.7, and `apply_vibrancy` / `NSVisualEffectView` on older macOS. Its newer builder can reparent a WebView via `content_view`; transparent window and transparent HTML are needed, and its Tauri example uses `macOSPrivateApi: true`. Select by OS availability and test actual packaged WebKit compositing, text contrast, reduced transparency and resizing. `NSGlassEffectView` is Apple's [documented AppKit class](https://developer.apple.com/documentation/appkit/nsglasseffectview); distinguish that public class from private Tauri/WebKit configuration needed by a particular transparency technique. Tauri explicitly warns its private API setting affects App Store acceptance; evaluate distribution early. The separately maintained [tauri-plugin-liquid-glass](https://github.com/hkandala/tauri-plugin-liquid-glass) claims older-macOS fallback but describes its implementation as private and experimental; assess maintenance and private selectors before choosing it. An [open window-vibrancy issue](https://github.com/tauri-apps/window-vibrancy/issues/229) reports packaged WebKit crashes in a specific macOS 27 configuration; this is a report, not a general verdict.

### Watching, incremental parsing and aggregates

Use [notify](https://docs.rs/notify/latest/notify/) recursive FSEvents on parent roots, debounce/coalesce, and rescan on startup and after lost events; notify warns of editor replacement and unowned-file/FSEvents limitations, with polling fallback. Track canonical file identity, size, mtime, parser version, committed byte offset and incomplete tail. Parse only complete newline-terminated records; on truncation, rotation, replacement or parser upgrade, rebuild affected source contributions instead of adding twice. JSON session snapshots and SQLite inputs need update/replacement logic, not append-only assumptions. Never persist raw lines or message content. Bound work off the UI thread; stream records, limit memory, batch updates and handle permission errors gracefully.

A local [rusqlite](https://docs.rs/rusqlite/latest/rusqlite/) database is reasonable for normalized, content-free events, provenance, checkpoints, per-day/model aggregates, and quota snapshot timestamps. Use transactions to atomically commit aggregates and offsets; support recomputation and deletion when a source is truncated/deleted. Open other applications' SQLite databases read-only, respecting WAL/locking; avoid `immutable` for live databases. Quota is a separate last-good observation with age/error, not a summed event ledger.

### Keychain access

Rust's [security-framework](https://docs.rs/security-framework/latest/security_framework/) exposes Security.framework generic-password and item queries; the CLI's existing item may require user approval even when the app knows its service name. Request access only for an explicitly enabled provider, avoid logging or persisting credentials, suppress background interaction and provide an explicit retry if locked/denied. macOS ACLs, code-signing identity, app sandbox/keychain access groups, item recreation and credential rotation can affect access. CodexBar documents that a grant can be reset on Claude credential recreation and uses user-action prompt policies: [Keychain notes](https://github.com/steipete/CodexBar/blob/main/docs/claude.md). Do not assume one app can silently read another's item; never modify or refresh shared credentials without a robust ownership strategy.

## Recommended v1 scope

1. **Claude Code + Codex local history**, including incremental parsing, tested dedup, model attribution, clear local coverage and API-equivalent cost labels. Highest value, observed on this machine, no credentials needed.
2. **Codex live limits via app-server**, with local snapshot and freshness as fallback; **Claude OAuth limits** as explicit opt-in, with Keychain consent and graceful unavailable states. Keep quotas separate from token totals.
3. **Gemini CLI and Pi local history** as straightforward additional adapters after fixture validation; preserve unknown fields and model attribution instead of guessing.
4. **Tray panel, dynamic title and native glass/vibrancy fallback**, tested on packaged macOS builds; expose accessibility, refresh age and a clear quit path.
5. **Later:** OpenCode, Copilot, Cursor, Droid, Kimi/Qwen and Amp adapters; then opt-in organization billing integrations. Prioritize by actual users and maintenance cost, especially undocumented endpoints, SQLite schema drift, account matching and credential access.
